# Repository guidance

- Развивайте проект итерационно как существующий работающий продукт: сначала используйте текущую архитектуру и код, предпочитая минимально инвазивные изменения.
- Не выполняйте большие рефакторинги, переписывание legacy-кода или архитектурные улучшения «заодно». Если задача требует серьёзной перестройки, остановитесь и опишите проблему.
- Стек: React / Next.js, legacy browser JS, Vinext / Vite, Next route handlers / Cloudflare Worker, D1 и Drizzle. D1 — текущая серверная база цифровой копии.
- Админ-панель управляет backend-данными цифровой копии. Для рабочих бизнес-сущностей она должна читать и изменять те же данные, что пользовательский ЛКП; не создавайте для неё параллельные копии основных сущностей.
- Для серверизованных сущностей D1/backend является каноническим источником: ЛКП и Админ-панель работают с одними серверными записями без независимых бизнес-копий.
- Для сущности, переведённой на backend/D1, клиент может хранить только временное UI-состояние и не должен восстанавливать или поддерживать независимую постоянную бизнес-копию.
- Внутренние технические ID могут иметь любой безопасный формат. В интерфейсах показывайте существующий естественный бизнес-номер либо короткий автоматически назначаемый public/business ID для сущностей без такого номера.
- Инвариант магазина: один товарный заказ = одна Организация + один Вендор. Заказы одного оформления связаны общей Корзиной, но остаются отдельными заказами.
- Связанные бизнес-данные не удаляйте физически, если это ломает историю; используйте архивирование или неактивное состояние.
- В быстром режиме локальных итераций запускайте только релевантные тесты. Полный test suite, production build, полный lint и браузерный регресс выполняйте перед commit/push/publish либо после существенных архитектурных изменений.
- Commit, push и Sites publish выполняйте только по отдельной команде пользователя.
- Не изменяйте `.openai/hosting.json` и конфигурацию Sites без отдельной задачи.
