# Repository guidance

- Перед работой обязательно прочитайте `README.md`: там описана фактическая архитектура цифровой копии.
- Работайте короткими итерациями, переиспользуйте существующую реализацию и не выполняйте рефакторинг «заодно».
- Не усложняйте browser-only архитектуру без необходимости; ЛКП и Админ-панель должны использовать общие бизнес-объекты.
- Все browser-only сущности и reset demo data должны работать через единый storage layer; UI не поддерживает независимые постоянные копии состояния.
- Поддерживайте `README.md` актуальным после существенных изменений.
- В обычной итерации запускайте только релевантные проверки; полный прогон выполняйте на контрольных точках и перед публикацией.
- Commit, push, merge и publish выполняйте только по отдельной команде пользователя.
- Если задача конфликтует с `README.md` или требует крупной архитектурной переделки, остановитесь и сообщите об этом.
